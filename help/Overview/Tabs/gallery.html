Gallery Tab — How It Works

Rewritten 27 October 2026 against the current code. The earlier page described a single gallery.js and listed risks found in a pasted copy; the tab is now five files under ui/gallery/, scripts run through the shared script runner, and the manifests come from the shared manifest system.

Gallery is a browser over three collections, or domains: Ideabook and Patterns (images) and Scripts (scripts that draw). Each has its own subtab of category frames. Choosing an item opens one shared Results subtab, labeled Images or Drawings, with Prev/Next.

The files

FileOwns
gallery.jsGalleryTabSpec, GalleryController; init / restore / save; loading the three domains' manifests
galleryNav.jsthe three domain subtabs and the Results subtab; the category views
galleryResults.jsshowing an image (with thumbnails) or running a script; Prev/Next; normalizing entry paths
galleryMenuCmds.jscaption ("category: title", Prev/Next, menu) and its commands (Help, Show Script, Notes, Edit Manifest, Archive); the Commands panel
galleryState.jscurrent domain, category, list and index

Where the content comes from

/gallery/<Domain>/directoryRegistry.json        the list of categories
/gallery/<Domain>/<Category>/manifest.json      the items in one category
/gallery/<Domain>/<Category>/images/thumb_<filename>.png

ensureGalleryCacheLoaded() asks the shared manifest system for gallery/Ideabook, gallery/Patterns and gallery/Scripts. getGalleryCache() returns the three category maps from manifest.getCategoryMap(). (galleryState.js still declares a galleryCache variable; the lookups no longer use it.)

State

uiState.gallery.saved = {
  view:     "categories" | "results",
  domain:   "Ideabook" | "Patterns" | "Scripts",
  category: string | null,
  index:    number | null
}

The tab rewrites saved every time you move, so setUI.js uses restore() when you return, and Gallery reopens exactly where it was. Gallery remembers one Results context only: the Results subtab always means "the last thing chosen". saved also goes to session storage, but rehydrateGalleryState(), which would read it back after a page reload, is not called.

The module state in galleryState.js (current list and index) drives Prev/Next. It is written together with saved by the same functions, so the two stay in step.

Results

  • Images (Ideabook, Patterns): the image in #text, a thumbnail grid of the category in #action with the current one marked; clicking a thumbnail shows it.
  • Drawings (Scripts): /gallery/Scripts/<category>/<filename> is run with runScriptByPath() into #sketchpad, controls enabled. No thumbnail grid.

Prev and Next move within the current category's list.

Restore details

  • If the remembered category has vanished (after a rebuild), Gallery falls back to that domain's categories.
  • An index past the end is pulled back to the last item.

Leftovers and shims

  • normalizeGalleryEntryPath() strips a leading Category/ from entry paths that include it. A manifest rule ("paths are relative to the category folder") is not enforced yet; this covers older entries.
