Draw Tab — How It Works

Rewritten 27 October 2026 against the current code. The earlier page described a single draw.js; the tab has since been split into seven files under ui/draw/, and it gained secondary objects (saved parameter variations).

The Draw tab shows one registry object at a time on the shared canvas, with its controls. It is a small tab system inside the main one: a permanent Categories subtab that lists every drawRegistry object, plus one subtab per object you open.

The files

FileOwns
draw.jsDrawTabSpec, DrawController, init / restore / save, and the launch intent from Home
drawNav.jsthe subtab bar: open, switch, close; the dirty mark; secondary objects (find, list, load)

drawMenuCmds.jscaption bar and its menu; Save / Copy / Reset; PNG and Pattern export; secondary save and archive; the Commands panel
drawTabState.jsone shared value: the set of registry ids that have secondaries on disk
secondaryObjects.jsthe requests to the Node service that save, list, load and archive secondaries

State

uiState.draw = {
  activeSubtab: "tab-categories" | "tab-<object name>",
  tabs: {
    "tab-categories": { type: "categories" },
    "tab-parabola":   { type: "object", drawRegistry: <the registry entry>,
                        dirty, parameters, showControls,
                        redrawHandler, onParamChange }
  },
  saved: null
}

An object subtab holds the registry entry itself, not a copy (contrast Figures, where each layer gets its own instance). Its parameters is the entry's own params object. redrawHandler and onParamChange are attached by drawActiveTab() for the parameter controls to call.

Activation: init, and why restore never runs

setUI.js decides how to show a tab: init(true) if the tab is flagged needsUpdate; otherwise restore() if uiState.draw.saved is set; otherwise init(false). Nothing ever sets uiState.draw.saved (setUI does not call save() on the way out), so Draw always runs initDrawTab(). That is fine in practice: initDrawTab() rebuilds the subtab bar from uiState.draw.tabs and switches back to the active subtab, so open objects survive a trip to another tab. restoreDrawTab() and saveDrawState() exist but are not reached.

initDrawTab() in order:

  1. Starts finding which objects have secondaries (asynchronous; redraws the category list when done).
  2. Clears the regions, labels and wires the Commands button.
  3. Rebuilds the subtab bar from uiState.draw.tabs (or creates Categories if there are none).
  4. If Home left a launch intent for Draw (uiState.launch), consumes and clears it and opens that object in a new subtab.
  5. Otherwise switches to the remembered subtab, or Categories.

Opening, switching, closing

  • addDrawSubtab(item) makes the subtab id from the object's name ("tab-" + name, spaces to dashes, lower case), calls the entry's init(), arms the interactor if the object is interactive and has handles, records the tab, and draws it.
  • switchTab(tabId) marks the button active, disarms the interactor, clears the regions, and shows Categories or the object (draw, caption, re-arm the interactor).
  • deleteTab(tabId) removes the button and the state and switches to a neighbor.

Drawing: drawActiveTab()

  1. Show #sketchpad-wrapper; put the shared canvas into #sketchpad; clear it.
  2. Size the "interaction" and "guides" overlay canvases to match.
  3. Attach redrawHandler (this function) and onParamChange (mark dirty).
  4. Build the controls with buildParameterControls(state, "tab-draw", true).
  5. entry.update(params), entry.draw(), then the scaffold guide (a dashed gray line along elements.l1, for objects that have one).

Caption menu and commands

The caption shows the object's name and a "v" menu built each time it opens: Help, Notes, Save as PNG, Save as Pattern, Copy Object, Reset Parameters, then either Save as Secondary (for a primary object) or Save Secondary and Archive Secondary (for a loaded secondary). The Commands button opens a maintenance panel (Rebuild & Validate through the Node service).

Secondary objects

A secondary is a saved set of parameter values for one registry object, kept on disk by the Node service (secondaryObjects.js). On the Categories view, an object that has secondaries shows a ">" button that lists them; choosing one loads its values into a subtab. drawTabState.js holds the set of ids that have any, filled by updateSecondariesDiscovery().

Known gaps (still true on 27 October 2026)

  • Two subtabs of one object collide. The id comes from the name, and the subtab holds the shared registry entry, so opening the same object twice gives one id and one set of parameters.
  • Restore is never used (above). If whole-page reload persistence is wanted, it needs a real save call and a restore path that rebuilds subtabs from saved keys and parameters.
  • Handles are drawn only for objects marked interactive with a params.points array.
