Home Tab — How It Works

Rewritten 27 October 2026 against the current code. The earlier page described a single home.js; the tab is now six files under ui/home/. Two things changed in behavior: images now show in #text (not #sketchpad), and the Home manifest now lives in the shared manifest.cache instead of a private cache.

Home is a dispatcher. It reads one flat list, /home/manifest.json, groups the entries by their status, and shows one category frame per status. Clicking an entry either shows it here (a script on the canvas, or an image) or, for a built-in Draw object, opens the Draw tab on it.

The files

FileOwns
home.jsHomeTabSpec; init / restore / save; ensureHomeSavedState()
homeNav.jsthe two subtabs, switching between Categories and Results, the category frames and what a click does, launching Draw
homeManifest.jsloading /home/manifest.json, grouping by status, refreshing after an edit
homeResults.jsshowing the chosen entry: run a script or load an image; the render token
homeMenuCmds.jscaption bar with the file's full path; menu (Help, Show Script, Edit Manifest); the Commands panel
homeState.jsthe grouped manifest and the render token

State

uiState.home.saved = {
  view:         "categories" | "results",
  activeStatus: string | null,
  activeIndex:  number | null,
  activeEntry:  the manifest entry object | null
}

Unlike the other tabs, Home's saved is already filled in by uiState.js, so setUI.js always calls restore() for Home (after a manifest rebuild it calls init(true) instead). Both end in switchHomeView(saved.view), so Home always comes back to what it last showed. saveHomeState() exists but is never called; the state is written as you click.

Two views

  • Categories: clears the caption, the canvas area and #action, then draws the status frames into #text (or "loading..." until the manifest arrives).
  • Results: shown only once an entry has been chosen (the Results subtab appears when activeEntry is set). Runs renderHomeResults().

The subtab bar is built by the shared buildSubtabBar() helper from a small description (an "adapter"): the two tabs, which one is active, and a condition that hides Results until there is something to show.

What a click does

  • An entry with sourceType: "drawRegistry" is launch-only. Home resets its own view to Categories, writes a launch intent into uiState.launch (pending, from home, to draw, the registry key), and calls setUI("draw") through a dynamic import() (setUI.js imports Home, so Home cannot import it at load time). Draw consumes and clears the intent.
  • Any other entry is stored as activeEntry and shown in Results.

Results

  • A .js path is run with runScriptByPath() (scriptRunner.js) on the shared canvas in #sketchpad, with its parameter controls in #action.
  • An image path (png, jpg, jpeg) is loaded and shown in #text, at most 800 by 800.
  • Anything else shows an error and throws.

The render token. Each Results render takes a new number from incrementHomeResultsRenderToken(). A slow image load checks, when it finishes, that its number is still the latest; if you clicked something else meanwhile, it quietly gives up instead of overwriting the newer result.

The manifest

/home/manifest.json is a flat array (no category folders, no directory registry). It is read with fileLayer.loadJSON() and kept in manifest.cache["home"], so the shared cache invalidation clears it like any other. Entries whose status is missing or blank are skipped; a non-object entry is an error.

Caption and commands

In Results the caption shows the title and, just before the menu button, the entry's full path. The menu has Help, Show Script and Edit Manifest. The Commands panel runs Rebuild & Validate, resyncs, re-runs initHomeTab(), and prints the report; it also has a Help button.
