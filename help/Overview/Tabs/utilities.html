Utilities Tab — How It Works

Rewritten 27 October 2026 against the current code. The tab is now five files under ui/utilities/, and scripts run through the shared script runner instead of being imported here.

Utilities runs small helper scripts. Tools scripts produce text or HTML, shown in #text. Lab scripts draw on the shared canvas. A third subtab, Result, appears after the first run and re-runs the last script.

The files

FileOwns
utilities.jsUtilityTabSpec; init / restore / save; loading the Tools and Lab manifests; refreshing after a manifest edit; the Commands panel
utilitiesNav.jsthe Tools / Lab / Result subtabs and switching between them
utilitiesDisplay.jsthe category frames, what a click does, running a script, showing a text result
utilitiesMenuCmds.jscaption ("category: title") and menu (Help, Show Script, Notes, Edit Manifest, Archive)
utilitiesState.jscurrent domain, category, list, index, and whether anything has run

Where the scripts are

/utilities/Tools/<Category>/<entry.path>
/utilities/Lab/<Category>/<entry.path>

Each group has a directory registry and per-category manifests, read through the shared manifest system (utilities/Tools, utilities/Lab).

Running a script: runUtilityEntry(subtab, category, entry)

  • Lab: runScriptByPath(path, "canvas", ...) into #sketchpad, controls in #action.
  • Tools: runScriptByPath(path, "text", ...); a string result is kept in uiState.utilities.lastResult and shown in #text.
  • Then the caption is set. An error is shown in #text and rethrown.

A click on an item records the subtab, category and entry in uiState.utilities, marks that something has run (which makes the Result subtab appear), and runs it.

State

uiState.utilities = {
  activeUtilityTabId:    "tab-tools" | "tab-lab" | "tab-result",
  lastUtilitySubtab:     "Tools" | "Lab",
  activeUtilityCategory: category name,
  activeUtilityItem:     the manifest entry,
  lastResult:            last Tools output (HTML),
  saved:                 null
}

Result is reproducible because the three remembered values rebuild the script's path.

Activation

Nothing calls saveUtilityState(), so uiState.utilities.saved stays null and setUI.js always calls initUtilityTab(false). Init reloads the manifests, rebuilds the subtabs, and switches to activeUtilityTabId, which is remembered in uiState.

Probable glitch (read from the code, not tried). Init with restored = false also resets "has anything run" to false, which hides the Result subtab. If you leave Utilities while on Result and come back, init switches to Result (re-running the script) while the Result subtab button is hidden.

Commands panel

Rebuild & Validate goes through the Node service, clears the manifest cache and marks every tab needsUpdate, then re-runs initUtilityTab(false) and prints the report.

After a manifest edit (Edit Manifest, Archive) the tab instead calls refreshUtilitiesFromManifestEdit(): it drops the cached Tools, Lab and Home manifests and reloads the two groups, finds the remembered item again by its path, and fails loudly if it is gone.
