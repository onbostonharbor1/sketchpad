utilities.js — Utilities Tab Controller

This page describes the role of ui/utilities.js in Sketchpad. It is written as “raw help HTML” so it can be dropped into the help system as-is.

Purpose

utilities.js implements the Utilities tab as an independent subsystem. It follows the same high-level model as the converted Patterns/Gallery tabs:

  • Loads manifest data once and caches it locally in this module
  • Builds a fixed subtab bar (Tools / Lab / Result)
  • Renders category frames using categories.js
  • Runs a selected utility script via dynamic ES-module import
  • Displays output deterministically in the shared regions (#text, #sketchpad, #caption, #action)
  • Saves just enough UI state into uiState.utilities so Result can be restored

Key Responsibilities

1) Load and cache Utilities manifests

On initialization, the file loads the two manifest groups: utilities/Tools and utilities/Lab. It also loads each group’s directory registry via manifest.getRegistry(). These are combined into a local cache:

  • utilitiesCache.Tools[category] = [entries...]
  • utilitiesCache.Lab[category] = [entries...]

This cache is module-local and is treated as the “read model” for rendering category frames. The Utilities tab does not add new manifest structures; it consumes the manifest output exactly as provided.

2) Provide a fixed subtab bar

setUtilitySubtabs() builds the three subtabs:

  • Tools — runs scripts that typically produce HTML/text output in #text
  • Lab — runs scripts that draw into the canvas (#sketchpad)
  • Result — a “replay” tab that reruns the last selected script deterministically

Subtab activation is enforced by activateUtilitySubtab(tabId), which is fail-fast: if the expected DOM structure is missing, it throws.

3) Render categories using categories.js

setUtilityCategories(which) creates a frames array that renderCategories("text", frames) can display. Each frame corresponds to one category directory under Tools or Lab, and each item’s onClick delegates to onUtilityItemClick(...).

The Utilities tab does not implement its own category UI. It only produces the descriptor array.

4) Run scripts via dynamic import

runUtilityEntry(subtab, category, entry) is the execution engine. It constructs the import path as:

/utilities/<Tools|Lab>/<Category>/<entry.path>

It then imports the module with a cache-buster query string (?t=Date.now()) so edits are visible immediately during development.

Contract: the module must export a function named runPattern(). If it does not, Utilities throws an error. This is intentional fail-fast behavior.

5) Handle Lab vs Tools output regions

Utilities treats “Lab” scripts differently:

  • It moves window.drawCanvas into #sketchpad
  • It clears the canvas to white before running the script
  • It does not assume HTML output in #text

For non-Lab scripts (Tools), the returned value from runPattern() is treated as HTML and displayed via displayUtilityResult(html).

6) Caption and “Show Script” menu

setUtilityCaption(...) applies a consistent caption rule:

  • Tools/Lab: "{category}: {title}"
  • Result (no category): "{title}"

The caption menu contains a “Show Script” item that opens the current script file path in a new browser tab. This is implemented via menuManager.

State Model

Utilities uses uiState.utilities to remember enough information to restore the last run item. The important fields are:

  • activeUtilityTabId — which subtab is active (Tools/Lab/Result)
  • lastUtilitySubtab — which group the last item came from (Tools or Lab)
  • activeUtilityCategory — the category folder needed to reconstruct the import path
  • activeUtilityItem — the manifest entry object
  • lastResult — cached HTML result for redisplay (used when returning to Result)
  • saved — a snapshot used by restoreUtilityTab()

The key design point: Result is deterministic because it reruns the same module import path derived from (lastUtilitySubtab, activeUtilityCategory, activeUtilityItem.path).

Lifecycle

init

  • Clears shared regions via clearDivs()
  • Wires the Commands button
  • Ensures uiState.utilities exists (initial default state)
  • Loads manifests and builds utilitiesCache
  • Builds subtabs and switches to the chosen subtab via switchUtilityTab(tabId)

restore

  • Ensures subtabs exist
  • Restores the active subtab and reruns/redisplays the last script when possible
  • If saved state is missing, falls back to a cold init

save

  • Copies the minimal restoration snapshot into uiState.utilities.saved
  • Returns the same object as informational output for the TabSpec contract

Commands Button (Offcanvas)

Utilities includes a maintenance offcanvas invoked by the Commands button:

  • “Rebuild & Validate” calls nodeRebuildAndValidateManifests()
  • Then it forces a manifest cache drop and reloads the Utilities cache
  • Finally it re-renders the current view deterministically and prints a report

This file does not implement the Node logic; it only triggers it and renders the returned report.

What utilities.js Does NOT Do

  • It does not define drawing primitives or geometry
  • It does not edit manifests directly (it consumes manifest output)
  • It does not implement category rendering (delegates to categories.js)
  • It does not provide a custom parameter-controls system for Utilities scripts

Files It Depends On

  • uiState (global) — persistent UI state for Utilities
  • manifest.js — reads manifest data and registries
  • categories.js — renders category frames from descriptor arrays
  • caption.js and menuManager.js — caption bar and menu
  • ui_utilities.js — shared UI helpers (clearDivs, commands offcanvas)
  • nodeLayer.js — dispatches rebuild/validate to the Node service
