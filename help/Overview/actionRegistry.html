actionsRegistry.js defines a small, declarative registry of caption-menu actions used throughout the Sketchpad UI. It centralizes how menu items are constructed so that individual tabs (Draw, Patterns, Gallery, etc.) do not hard-code menu behavior.

The file exports a single object, MENU_ACTIONS, whose keys are action names (e.g. help, showScript, duplicate). Each action provides a builder(menuContext) function.

A builder does not execute the action directly. Instead, it returns a fully formed menu-item descriptor that can be passed to menuManager.open(). This keeps menu rendering and menu behavior cleanly separated.

The menuContext object is supplied by the calling tab and contains only the data that specific action needs. Different actions expect different fields in menuContext.

In effect, this file acts as a dispatch table: tabs select which actions they want by name, and actionsRegistry.js defines how those actions are built and wired.

Defined actions

  • help
    A shared action used across multiple tabs. The builder delegates to menuManager.buildHelpItem(), which is manifest-driven.

    Expected menuContext fields:

    • tabName – the active tab (for example, "draw")
    • itemName – the registry key or item identifier

    The returned menu item opens the appropriate help content for the current tab and item.

  • showScript
    A shared action that displays the source code for the current item in an off-canvas panel.

    Expected menuContext fields:

    • scriptPath – path to the JavaScript file to display
    • itemName – used as the title in the off-canvas header

    The builder returns a menu item labeled “Show Script”. When clicked, it calls showScriptOffcanvas(), which fetches the script, escapes it, and renders it for viewing.

  • duplicate
    A Draw-specific action. It does not know how duplication works internally.

    Expected menuContext fields:

    • duplicateHandler – a function supplied by draw.js

    The builder returns a menu item labeled “Duplicate”. Clicking it simply invokes the provided handler. This keeps draw-specific logic out of the shared menu system.

Overall, actionsRegistry.js provides a declarative, extensible mechanism for defining caption-menu behavior. New actions can be added in one place, and tabs can opt into them by name without duplicating wiring logic.
