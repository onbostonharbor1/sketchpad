```html Help Treatise — ui_utilities.js (mixed utilities / what it controls)

This “different” file: what it controls (and why it feels different)

Yes — this file is different from the others you posted. Most of your other modules are about ONE subsystem (menus, overlays, script running, tab orchestration). This one is a grab-bag of shared UI utilities that touch multiple subsystems: clearing regions, overlay clearing, offcanvas display, thumbnail grids, category descriptors, help manifest loading, and commands button wiring.

So the right “doc style” here is not “explain the whole program,” but “summarize the controlled surfaces” (the things this file directly mutates).

1. Controlled surfaces (the DOM + globals this file directly manipulates)

1.1 Core shared regions (by id)

clearDivs() directly clears innerHTML of:

  • #action (left controls area)
  • #caption (caption bar area)
  • #text (text output area)
  • #sketchpad (canvas container area)
  • plus optionally one extra id passed as an argument

1.2 Canvas overlay layers (via overlayManager.canvasLayers)

clearDivs() also clears the overlay SVG/HTML layers:

  • overlayManager.canvasLayers["interaction"]
  • overlayManager.canvasLayers["bbox"]
  • overlayManager.canvasLayers["nodes"]
  • overlayManager.canvasLayers["guides"]

It does this generically by iterating over all keys in overlayManager.canvasLayers. So any future canvas layer registered there is also cleared.

1.3 Overlay container visibility

clearOverlaysForTabSwitch() directly sets:

  • #overlayContainer.style.display = "none"
  • and then calls overlayManager.clearAll() (panel overlays)

1.4 The offcanvas shell

Several functions assume a permanent Bootstrap offcanvas panel exists:

  • #offcanvasPanel
  • #offcanvasPanel .offcanvas-title
  • #offcanvasPanel .offcanvas-body

Functions that write into it:

  • showOffcanvas(title, text) (creates a <pre> node)
  • showSharedOffcanvas(title, text) (writes pre via innerHTML)
  • showScriptOffcanvas(scriptPath, titleText) (fetches source, then writes a <pre>)
  • showCommandsOffcanvas({title, buildBody}) (calls buildBody(bodyEl))
  • showOffcanvasPanel({title, bodyHtml}) (raw HTML injection)

1.5 Commands button

These functions assume #commandsButton exists:

  • setCommandsButtonLabel(label) sets textContent
  • setCommandsButtonHandler(onClick) sets btn.onclick deterministically
  • setCommandsButton(label, onClick) replaces the button node (clone strategy) then wires click

1.6 Thumbnail grids

These functions own a small “thumbnail panel” UI pattern:

  • renderThumbnailGrid(targetId, items, buildSrc, onClick)
  • markSelectedThumbnail(actionDivId, selectedIndex)

They assume thumbnails are: <img class="thumb-image">, and selection is represented by CSS class thumb-selected.

1.7 Help manifest caching

The bottom section is effectively its own module:

  • helpManifest global cache variable
  • loadHelpManifest() fetches /help/manifest.json once, validates object shape, caches it

2. Why this file feels “wrong” (it contains duplicates and incompatible patterns)

Your pasted file is not just “utilities.” It contains multiple overlapping implementations of the same concept, because it looks like it grew by accretion.

The biggest source of confusion here is that you have more than one way to do the same job. That makes it hard to know what the “real” API is.

2.1 Offcanvas: three overlapping entry points

  • showOffcanvas(title, text)
  • showSharedOffcanvas(title, text)
  • showOffcanvasPanel({title, bodyHtml})

They differ in:

  • how content is inserted (DOM nodes vs innerHTML string)
  • how bootstrap is invoked (new bootstrap.Offcanvas(panel) vs getOrCreateInstance)
  • whether there is a fallback non-bootstrap “manual show” mode

Practical result: if you call “the wrong one,” you may get:

  • duplicate Offcanvas instances
  • different formatting
  • different failure behavior

2.2 Commands button: two incompatible wiring styles

  • setCommandsButtonHandler(onClick) sets btn.onclick
  • setCommandsButton(label, onClick) clones/replaces the node, then adds listener

These are not equivalent:

  • The clone strategy intentionally wipes all previous listeners, but it also invalidates any references to the old DOM node.
  • The onclick strategy overwrites only onclick, but does not wipe listeners added via addEventListener elsewhere.

2.3 Help manifest is duplicated elsewhere

Earlier you posted a separate menuManager.buildHelpItem() that calls loadHelpManifest(). In your pasted file, loadHelpManifest() is defined at the bottom. That means this “utilities” file is also acting as a help-manifest module.

3. If you want “brief comments for each control”: what counts as a control in this file?

This file is not “parameter controls.” The “controls” it manages are UI shells / view helpers:

  • Core regions: action/caption/text/sketchpad clearing
  • Overlay layers: panel overlays (help/forms/debug) and canvas overlays clearing
  • Offcanvas panel: a long-text viewer (script source, commands, etc.)
  • Commands button: label + handler (and sometimes full handler reset)
  • Thumbnail panel: render a grid + mark selection
  • Help manifest cache: load once, share everywhere

So “brief comments” here should explain the purpose of each exported helper as a UI surface controller.

4. Recommended reading order for understanding (not a redesign)

If your goal is understanding (not refactoring), read in this order:

  1. clearDivs() (what gets cleared on tab/view change)
  2. clearOverlaysForTabSwitch() (panel overlays reset)
  3. showScriptOffcanvas() (how “Show Script” is implemented)
  4. renderThumbnailGrid() + markSelectedThumbnail() (thumbnail UI pattern)
  5. loadHelpManifest() (help enable/disable data source)
  6. Commands button helpers (how per-tab menus are invoked)

5. One-sentence summaries of each exported function (the “controls” list)

  • clearDivs(extraId) — clears the core tab regions and wipes all canvas overlay layers.
  • clearOverlaysForTabSwitch() — hides the overlay container and clears panel overlays.
  • initOffcanvasHandler() — ensures the Bootstrap offcanvas panel exists and is initialized once.
  • showOffcanvas(title, text) — shows long text in offcanvas via a created <pre> node.
  • showSharedOffcanvas(title, text) — shows long text in offcanvas via innerHTML (with fallback if bootstrap missing).
  • showScriptOffcanvas(scriptPath, titleText) — fetches a script file and displays the literal source in offcanvas.
  • wrapIndex(i, len) — wraps indices for cyclic prev/next navigation.
  • renderThumbnailGrid(targetId, items, buildSrc, onClick) — renders a thumbnail panel and wires click handlers.
  • markSelectedThumbnail(actionDivId, selectedIndex) — toggles the CSS selection marker on the chosen thumb.
  • buildCategoryDescriptor(groups, itemLabelFn, onClickFn) — converts grouped items into the category descriptor structure consumed by categories.js.
  • loadHelpManifest() — fetches and caches /help/manifest.json once and returns it for all tabs.
  • setCommandsButtonLabel(label) — sets the Commands button label text.
  • setCommandsButtonHandler(onClick) — deterministically replaces the Commands button onclick handler.
  • showCommandsOffcanvas({title, buildBody}) — populates the shared offcanvas with a dynamically built DOM body.
  • setCommandsButton(label, onClick) — replaces the Commands button node to wipe prior handlers, then wires a fresh click.
  • showOffcanvasPanel({title, bodyHtml}) — opens offcanvas with raw HTML body content.
  • escapeHtml(text) — escapes HTML special characters for safe insertion into innerHTML.

End of summary doc.
```
