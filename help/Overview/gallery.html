Gallery Tab (gallery.js) — Architecture and Behavior

This help page explains the current architectural shape and behavior of ui/gallery.js (the Gallery tab). It describes:

  • What Gallery owns (domains, subtabs, Results view)
  • The state model (what is persisted vs what is ephemeral)
  • The directory/manifest model used to build Gallery content
  • The view transitions (cold start, restore, category clicks, Results clicks)
  • Known mismatches and risk points (contract mismatches, state drift risks)
High-level summary
Gallery is a 3-domain browser (Ideabook / Patterns / Scripts) with fixed domain subtabs and one shared Results subtab created on demand and reused. Only one results context is remembered in uiState.gallery.saved.

A. What Gallery “owns”

A1. Domain subtabs (fixed)

Gallery has three fixed domain subtabs:

  • Ideabook
  • Patterns
  • Scripts

These are created by buildGallerySubtabs(). Clicking any of them:

  • Sets uiState.gallery.saved.view = "categories"
  • Sets uiState.gallery.saved.domain to that domain
  • Clears caption
  • Shows the category frames for that domain

A2. One shared Results subtab (created on demand)

Gallery also has one shared Results subtab that is created only when needed:

  • Created by ensureResultsSubtab(domain)
  • Reused for all domains once created
  • Label changes depending on domain:
    • Ideabook / Patterns: Images
    • Scripts: Drawings

Clicking the Results tab does not compute a new selection; it restores the one remembered results context stored in uiState.gallery.saved.

A3. Results content

Domain Results renderer What it displays Navigation model
Ideabook showGalleryResultsImages(domain, category, startIndex) An <img> in #text and a thumbnail grid in #action Prev/Next moves within the selected category list
Patterns showGalleryResultsImages(domain, category, startIndex) Same as Ideabook: <img> + thumbnails Prev/Next moves within the selected category list
Scripts showGalleryResultsScripts(category, index) Executes a script on the shared canvas in #sketchpad Prev/Next moves within the selected script list

A4. Maintenance offcanvas

Gallery wires the global Commands button to a Gallery Maintenance offcanvas:

  • Runs nodeRebuildAndValidateManifests()
  • Clears cached gallery manifests
  • Reloads and restores either categories view or results view based on uiState.gallery.saved

B. State model

B1. Persisted / restorable state: uiState.gallery.saved

Gallery’s restore logic relies on a single “remembered context” object: 

uiState.gallery.saved = {
  view:     "categories" | "results",
  domain:   "Ideabook" | "Patterns" | "Scripts",
  category: string | null,
  index:    number | null
};

This object is the source of truth for:

  • restoreGalleryTab()
  • Clicking the Results tab (ensureResultsSubtab() click handler)
  • Post-rebuild restore (refreshGalleryAfterRebuild())
Key rule
Gallery remembers exactly one Results context. Results is always “restore the last selection.”

B2. Ephemeral module state (local variables)

Gallery also maintains local module variables used for current rendering and navigation:

  • currentDomain
  • currentCategory
  • currentList
  • currentIndex
  • galleryCache

These are used by:

  • showPrevGalleryItem() / showNextGalleryItem()
  • Thumbnail selection handlers
  • Caption construction (title and menu wiring)
Important risk
If local module state and uiState.gallery.saved drift out of sync, Gallery can restore correctly but Prev/Next (or caption/menu actions) can act on a different list.

C. Directory / manifest model

Gallery expects a “domain registry + per-category manifest” filesystem layout: 

/gallery/<Domain>/directoryRegistry.json
/gallery/<Domain>/<Category>/manifest.json

Where:

  • directoryRegistry.json is an array of category names (strings)
  • Each category has a manifest.json which is an array of entries

Gallery loads these into a cache: 

manifest.cache.gallery = {
  Ideabook: { "CatA": [ ... ], "CatB": [ ... ], ... },
  Patterns: { "CatA": [ ... ], "CatB": [ ... ], ... },
  Scripts:  { "CatA": [ ... ], "CatB": [ ... ], ... }
};

The load/validation logic is in ensureGalleryCacheLoaded().

D. View transitions (what happens when)

D1. Cold start: initGalleryTab()

  • Resets module state
  • Loads cached manifests
  • Builds fixed domain subtabs
  • Wires Gallery Commands offcanvas
  • Sets defaults to Ideabook Categories view
  • Calls showIdeabookCategories(), activates Ideabook, clears caption

D2. Restore: restoreGalleryTab()

Restore behavior is determined by uiState.gallery.saved.view:

  • If view === "categories", show category frames for the saved domain.
  • If view === "results", ensure Results subtab exists, activate it, and restore results content:
    • Scripts: showGalleryResultsScripts(saved.category, saved.index)
    • Images: showGalleryResultsImages(saved.domain, saved.category, saved.index)

D3. Clicking a category item (Categories view)

  • Creates/activates Results subtab via ensureResultsSubtab()
  • Switches into Results view
  • Calls the appropriate renderer:
    • Ideabook/Patterns: showGalleryResultsImages()
    • Scripts: showGalleryResultsScripts()

D4. Clicking the Results subtab

Results tab click restores the single remembered results context:

  • Fails fast if there is no saved results context
  • Routes to Scripts or Images renderer based on saved.domain

E. Caption rule and navigation

E1. Caption title

Title rule implemented by updateGalleryCaption(domain, categoryLabel):

  • Title is "{category}: {title}"
  • For Scripts, categoryLabel is the script category name

E2. Prev/Next

  • Prev/Next always moves within currentList
  • Prev/Next updates:
    • currentIndex
    • uiState.gallery.activeItem
    • uiState.gallery.saved.index

E3. Menu items

Current menu behavior is domain-specific:

  • Scripts domain menu includes:
    • Show Script (offcanvas)
    • Edit Manifest Title
  • Other domains currently have no menu items in the shown snippet

F. Known mismatches and risk points

These are not “style notes.”
Each item below can cause a real bug or forces later contortions if left unaddressed.

F1. uiState import must exist

The pasted file references uiState extensively but the snippet does not include import { uiState } from "./uiState.js";. If that import is absent in the real file, Gallery will crash immediately.

F2. TabSpec regions omit "subtabs"

GalleryTabSpec.regions does not include "subtabs", even though Gallery builds and depends on #subtabs. If your tab framework uses the region list to clear/build UI, this is a contract mismatch.

F3. clearDivs() must not destroy subtabs

Many Gallery functions call clearDivs(). If clearDivs() clears #subtabs, then Gallery can erase its own subtab bar after creating it. This must be understood and enforced consistently (either “clearDivs never clears subtabs” or “Gallery must not call clearDivs in subtab-dependent flows”).

F4. Scripts Results UX differs from Images Results UX

Images Results builds a thumbnail grid in #action. Scripts Results clears #action and runs only the selected script. This is a deliberate UX difference; if later parity is desired, it requires explicit work.

F5. Scripts runner is a mixed-format compatibility layer

showGalleryScript() supports multiple script export shapes:

  • patternMeta + initPattern() + drawPattern() (custom controls)
  • runPattern(ctx) (single entry point)

This conflicts with the newer direction to standardize Gallery scripts (runPattern + scriptInfo + parameterControls). If the system is moving toward a single standardized script shape, showGalleryScript() is the convergence point.

F6. Canvas clearing for scripts is not robust

showGalleryScript() clears by filling white but does not reset transforms/composite state. If a previous script left the ctx transformed, subsequent scripts may render “off” or appear layered. Home uses a stronger reset approach (reset transform first, then clear).

F7. normalizeGalleryEntryPath() is a compatibility shim

The manifest rule is “entry.path is relative to the category folder,” but some manifests embed Category/filename. The normalizer strips that prefix so URLs resolve. This is correct as a transitional shim, but it signals that manifest normalization is not yet enforced.

G. One-sentence canonical description

Gallery is a 3-domain gallery browser (Ideabook / Patterns / Scripts) with fixed domain subtabs and one shared Results subtab created on demand and reused; it loads per-domain category registries and per-category manifests into a cached domain map; Categories view renders frames via renderCategories; selecting any item activates Results and stores one remembered results context in uiState.gallery.saved; Results displays either images (with thumbnails) or executes scripts on the shared canvas with Prev/Next navigation and domain-specific caption menu items.
