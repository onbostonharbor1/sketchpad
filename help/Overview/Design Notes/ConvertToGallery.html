DESIGN RULES — GALLERY SCRIPT CONVERSION (AUTHORITATIVE)

This document is the authoritative conversion contract for converting standalone drawing scripts into Gallery scripts.

It is meant to be pasted back verbatim before any future conversion request. No interpretation. No optimization. No “helpful” adjustments.

FOUNDATIONAL CONSTRAINTS (NON-NEGOTIABLE)

  1. There is exactly ONE canvas and ONE drawing context (ctx).
  2. ctx is predefined, global, and authoritative.
  3. All drawing code assumes ctx already exists.
  4. No script may create, cache, pass, alias, or resolve ctx.
  5. No script may reference window.ctx.
  6. If ctx does not exist, the system must crash loudly.
  7. Conversions MUST NOT introduce any ctx-related logic.

This rule exists because:

  • The entire Sketchpad system is built on a single shared coordinate space.
  • Overlays, nodes, handles, guides, and figures must interconnect exactly.
  • External standalone drawings must be drop-in compatible with Sketchpad.
  • Any ctx indirection risks breaking that guarantee.

All draw code uses ctx directly. Period.

PURPOSE OF CONVERSION

The conversion exists for ONE reason only: To make Gallery scripts look, read, and behave like drawRegistry entries, so that:

  1. You can mentally read any Gallery script the same way you read a drawRegistry entry.
  2. parameterControls can treat Gallery scripts and drawRegistry entries consistently.
  3. The conversion is mechanical, repeatable, and low-risk.

This is NOT:

  • A drawRegistry conversion
  • A refactor
  • An architectural redesign
  • A math rewrite

CANONICAL INTERNAL MODEL (MANDATORY)

Every converted Gallery script MUST implement the following internal vocabulary and lifecycle:

1. params

  • JSON-safe defaults.
  • Holds current UI values.
  • Replaces any previous parameters object.
  • Must NOT be used directly for drawing.

2. controls

  • Declarative metadata for parameterControls.
  • Schema must remain exactly as expected:
    • label
    • widget
    • min / max / step
    • options
    • default
  • Must never be mutated.

3. elements

  • Persistent runtime state.
  • Created exactly once in init().
  • Must have the shape: 
    elements = { element: { … } }
  • elements.element is the only object draw() reads from.
  • May contain:
    • normalized values
    • derived values
    • cached geometry
    • arrays, points, etc.

4. init()

  • Cold-start only.
  • Creates elements.
  • Seeds elements.element from params.
  • May validate initial values.
  • May compute derived values.
  • MUST NOT:
    • build UI
    • draw
    • reference parameterControls
    • touch ctx beyond assuming it exists

5. update(newParams)

  • Copies values from params into elements.element.
  • Handles all type normalization (parseFloat, parseInt, booleans).
  • Handles all validation (fail-fast).
  • Recomputes derived data.
  • MUST NOT draw.
  • MUST NOT create new element objects.
  • MUST NOT mutate controls.

6. draw()

  • Reads ONLY from elements.element.
  • Clears and draws deterministically.
  • Uses ctx directly.
  • MUST NOT read from params.
  • MUST NOT mutate params or controls.

runPattern() — GALLERY ENTRY POINT

runPattern() is the orchestrator.

It MUST perform the following steps in order:

  1. printTitle(scriptInfo.title)
  2. Compatibility alias setup 
    scriptInfo.parameters = scriptInfo.params
  3. init()

    Called exactly once per script load.

  4. buildParameterControls(scriptInfo, targetId, true)
    • targetId must not change.
  5. First draw
    • Must be explicit.
    • Typically via scriptInfo.redrawHandler().

No ctx handling of any kind occurs here.

PARAMETERCONTROLS COMPATIBILITY (MANDATORY BRIDGE)

parameterControls currently expects these fields:

  • scriptInfo.title
  • scriptInfo.controls
  • scriptInfo.parameters
  • scriptInfo.redrawHandler
  • scriptInfo.onParamChange (may be required even if empty)

Because the canonical model uses params/init/update/draw, a compatibility bridge is REQUIRED.

The bridge is:

1. scriptInfo.parameters

  • Alias to scriptInfo.params.

2. scriptInfo.redrawHandler

  • Must exist.
  • Must do exactly: 
    update(this.params);
draw();

3. scriptInfo.onParamChange

  • Must exist.
  • May be a no-op.
  • May alias redrawHandler if required.

This allows:

  • Immediate standardization
  • Zero changes to parameterControls
  • Safe batch conversion of many scripts

MECHANICAL CONVERSION CHECKLIST

For each script, do ONLY the following:

  1. Leave all math and drawing logic untouched.
  2. Rename parameters → params.
  3. Introduce elements and init().
  4. Implement update(params).
  5. Implement draw().
  6. Add compatibility aliases.
  7. Update runPattern() to follow the required sequence.

Nothing else.

WHAT MUST NEVER CHANGE

During conversion, DO NOT:

  • Touch ctx handling.
  • Add ctx parameters.
  • Add ctx caching.
  • Add safety wrappers for ctx.
  • Change geometry math.
  • Change coordinate systems.
  • Change colors or defaults.
  • Change canvas clearing behavior.
  • Change buildParameterControls usage.
  • Introduce new abstractions.

FAILURE MODES (DIAGNOSTIC MAP)

  1. Controls move, nothing redraws

    → Missing or broken redrawHandler.

  2. Drawing ignores control values

    → draw() reading params or stale locals instead of elements.element.

  3. Blank initial render

    → No explicit first draw in runPattern().

  4. Wrong numeric behavior

    → Type normalization missing in update().

  5. Extra testing burden

    → Conversion touched things it was not allowed to touch.

AUTHORITATIVE SUMMARY

A converted Gallery script:

  • Uses drawRegistry vocabulary.
  • Preserves Gallery execution semantics.
  • Assumes ctx exists and uses it directly.
  • Contains NO ctx logic whatsoever.
  • Is structurally uniform with every other converted script.
  • Requires minimal testing because nothing else changed.
