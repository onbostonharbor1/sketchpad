interactor.js — Handles You Can Drag

Rewritten 27 October 2026 against the current code. Since the earlier page: the handle presets changed (radius 5, grab range 10, red), handles can be selected and nudged with the arrow keys, they follow a layer's transform, the Figures centroid can take a press first, every move goes through one function (moveHandle) with before and after hooks for welds, and only the left button grabs. For the whole picture of dragging in Sketchpad (handles, discs, layers, welds) see "Point Dragging".

interactor.js draws an object's handles (its params.points) on the "interaction" overlay canvas and lets you drag them. One object is armed at a time. Draw, Figures and interactive scripts all use it.

Presets

PointPickerPresetsValueMeaning
handleRadius5drawn size of a handle, canvas pixels
hitTolerance10how close a press must be to grab one
idleColor#C91A09red: a handle at rest
activeColor#FE8A18orange: hovered, dragged or selected

The public functions

  • armInteractor(instance): disarms any previous object, then starts listening for this one. Does nothing if the object has no params.points. Also on window.
  • disarmInteractor(): removes the listeners, clears and hides the interaction canvas. Also on window.
  • refreshInteractor(): redraws the armed object's handles; used when something moves them without going through the interactor (the Figures centroid).

What the armed object may supply

PropertyUsed for
params.pointsthe handles themselves, in object space (required)
update(params)called after each move so the object rebuilds its geometry
redrawHandler()called after each move to redraw (Figures sets this); without it the Draw tab's active subtab is redrawn, or the object's own draw()
getTransform()the layer's transform (Figures). Handles are shown and hit in canvas space and stored in object space
yieldTo(x, y)true if the press belongs to something above the handles (the Figures centroid)
beforeMove(), afterMove()called around every move (Figures welds)

The mouse and keys

  • Left press within 10 px of a handle: that handle is dragged and also becomes the selected handle (orange, with a black outer ring). A press elsewhere clears the selection. If yieldTo says the press belongs to something else, the handles stay out of it. Other buttons are ignored.
  • Move while dragging: the handle is put exactly under the pointer (there is no "still a click" margin here; the smallest movement moves it). While not dragging, hovering turns a handle orange.
  • Release: the drag ends; the selection stays.
  • Arrow keys: move the selected handle 1 px (10 with Shift), in canvas directions. Ignored while the keyboard is in a text box, slider or list.

Listeners are on window, not the canvas, so a drag that strays off the canvas keeps going. All four are registered with one AbortController; disarming is one abort().

moveHandle(i, x, y): the one place a handle moves

  1. beforeMove(), if supplied.
  2. Canvas (x, y) to object space through getTransform(); write into points[i].
  3. onUpdate: the object's update(), then its redraw.
  4. afterMove(), if supplied.

Dragging and the arrow keys both go through it, so anything that has to react to a handle (welds) hooks in one place.

Things worth knowing

  • The object's handle array is changed in place; the object reads it back in its own update(). Objects that keep extra handles in that array (a Line's or Parabola's midpoint) decide in update() what a moved midpoint means (they slide the whole line).
  • Showing any panel overlay (help, forms) disarms the interactor (overlayManager.show).
