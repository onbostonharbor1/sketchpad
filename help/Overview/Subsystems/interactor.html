interactor.js serves as the bridge between static drawing parameters and user manipulation. It manages a dedicated interaction-layer canvas (via overlayManager) that sits atop the main drawing canvas, allowing users to move control points in real-time.

The module follows a "Subscription" model: a drawing instance (like a Star or Polygon) "arms" the interactor with its coordinate data, and the interactor handles the low-level mouse events, updating the instance's parameters directly.

Core Configuration: PointPickerPresets

The visual and physical behavior of the interaction handles is governed by a central preset object:

  • handleRadius: 3 – The visible radius of the handle circles.
  • hitTolerance: 7 – The "invisible" grab radius; clicks within this distance trigger a drag.
  • idleColor: "#0055BF" – LEGO Bright Blue; used for handles not currently being interacted with.
  • activeColor: "#FE8A18" – LEGO Bright Orange; used for hovered or dragged handles.

armInteractor(instance)

This is the primary public entry point. It connects a drawing class instance to the global interaction layer.

Sequence of operations:

  1. Cleanup: Automatically calls disarmInteractor() to ensure no zombie sessions exist.
  2. Validation: Checks for the existence of instance.params.points. If missing, it logs a warning and aborts (Fail-soft).
  3. UI Management: Disables pointer events on #next-prev-overlay to ensure the interaction layer receives all mouse input.
  4. Activation: Initializes the activatePointPicker logic, passing the point references and a specialized onUpdate callback.

Redraw Coordination:

When a point is moved, the interactor attempts to trigger a refresh in the following priority:

  • instance.redrawHandler() – The preferred unified update method.
  • instance.update() + instance.draw() – Fallback for legacy pattern structures.

disarmInteractor()

Public API to shut down the interaction layer. It executes the cleanup function returned by the active session, clears the deactivateCurrent reference, and hides the interaction canvas.

Internal Logic: activatePointPicker(points, config)

This internal function manages the lifecycle of a single interaction session using an AbortController for clean event listener removal.

Canvas Synchronization:

The interaction canvas is dynamically resized to match window.drawCanvas. This ensures that the coordinate system of the overlay perfectly matches the drawing surface regardless of window scaling.

State Tracking:

  • draggedIndex – Integer index of the point currently being moved.
  • hoverIndex – Integer index of the point currently under the cursor (triggers orange highlight).

Event Handling:

Listeners are attached to the window object rather than the canvas element. This is a deliberate design choice to "bypass the shield"—preventing other UI overlays from intercepting events while a drag is in progress.

  • mousedown: Performs a distance check (Pythagorean) against all points using hitTolerance.
  • mousemove: Updates hoverIndex for visual feedback. If a drag is active, it updates the x and y properties of the point object by reference and triggers the update callback.
  • mouseup: Releases the drag lock and resets state.

Architectural Note: Pass-by-Reference

The Interactor relies on the fact that instance.params.points is an array of objects. Because it modifies the objects within that array directly, the drawing instance's data is updated "in-place." The Interactor does not need to send data back to the instance; it merely needs to tell the instance when to redraw.
