parameterControls.js — Control Schema Flags & Rendering Rules

This document summarizes all control-schema flags and behavioral rules used by parameterControls.js. These flags determine how controls are interpreted, normalized, and rendered across the Draw and Scripts tabs of the Sketchpad UI.

1. Range Controls (widget: "range")

1.1 Numeric Range Configuration

  • def.min, def.max, def.step
  • Applied by both setRangeControl() and setRangeHeaderControl().

1.2 def.noButtons === true

  • Suppresses the small step buttons (< and >) normally placed beside the slider.
  • Used by both range styles.

1.3 def.rangeHeader === true

  • Selects the alternate “header-style” range UI.
  • Handled by setRangeControlUnified():
    • true → setRangeHeaderControl()
    • false → setRangeControl()
  • Makes range and rangeHeader interchangeable via schema flag.

1.4 def.rebuildControls === true

  • After a control changes value, the Action panel is rebuilt.
  • Triggers:
    • buildDrawParameterData(info)
    • renderParameterControls(info, data, tabId)
  • Supported by:
    • setRangeControl()
    • setRangeHeaderControl()
    • setRadioControl()

2. Hidden Controls (widget: "hidden")

  • Control is not rendered and consumes no space.
  • Implemented via setHiddenControl().

3. Static Text (widget: "staticText")

3.1 Conditional Visibility

  • def.showKey = "<boolean-parameter-key>"
  • If the referenced parameter is not true, the control is skipped.
  • Implemented in buildSingleControl().

4. Button Controls (widget: "button")

4.1 def.fullRow === true

  • Button spans both grid columns.
  • Otherwise it appears in the control column only.

4.2 def.redraw === true

  • After the button action runs, info.redrawHandler() is invoked.

5. Accordion Controls (widget: "accordion")

5.1 def.startOpen === true

  • Accordion section begins expanded.

5.2 def.redrawOnToggle === true

  • Calls info.redrawHandler() when the accordion is opened or closed.

5.3 Optional CSS Overrides

  • sec.listClass and sec.itemClass
  • Used when rendering accordion item lists.

6. Select & Radio Controls

6.1 def.options

  • Array of enumerated options.
  • Used by setSelectControl() and setRadioControl().

7. info.onParamChange (Optional)

  • If present, it is called after parameter updates.
  • No longer required by setRangeHeaderControl().

8. Interface Controls (def.control)

Interface Controls affect UI state but are not saved with drawing parameters. They are rendered into #interface-controls instead of the main Action panel.

8.1 How to Define

controls: {
  radius: {
    widget: "range",
    min: 10, max: 100,
    label: "Radius"
  },

  showGrid: {
    control: "checkbox",
    label: "Show Grid Overlay",
    default: false
  }
}

8.2 Behavior

  • Rendered separately from drawing parameters.
  • Automatically excluded from saved JSON.
  • Accessed via this.params.showGrid like any other parameter.

9. Rendering Pipeline Overview

9.1 buildParameterControls()

  • Normalizes schema into a control-data array.
  • Auto-detects environment (Draw vs Scripts).
  • Delegates to:
    • buildDrawParameterData()
    • buildScriptParameterData()

9.2 renderParameterControls()

  • Writes into the active tab’s #action area.
  • Clears and rebuilds #drawControls.
  • Routes interface controls to #interface-controls.
  • Skips hidden controls (null fields).

9.3 buildSingleControl()

  • Dispatches to the appropriate setXControl() function.
  • Handles conditional suppression for staticText.
  • Preserves button metadata (action, redraw).

10. Range Header UI Notes

The header-style range control uses a two-row layout:

  • Row 1: label + live value
  • Row 2: full-width slider

It requires:

  • info.parameters
  • info.redrawHandler()
  • tabId and key

11. Notes on Environment Detection

buildParameterControls() distinguishes Draw vs Scripts by inspecting the shape of sourceInfo:

  • Scripts: sourceInfo.controls exists.
  • Draw: sourceInfo.drawRegistry exists.

This allows the same renderer to support multiple tab types without hard-coding.

End of documentation.
