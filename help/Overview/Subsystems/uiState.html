uiState — The App's Memory

Rewritten 27 October 2026 against ui/uiState.js. The earlier page described a uiState.manifests area (manifests now live in manifest.js's own cache) and a simpler restore rule; it did not know about needsUpdate or the Figures state.

uiState is one plain object that remembers where the user is: which tab, what each tab is showing, what is selected. It is declared in ui/uiState.js, exported, and also put on window, so code can use the bare name uiState anywhere.

Rules

  • Data only. No functions, no DOM nodes. (A few tabs break this inside their own areas: Draw stores the registry entry itself in a subtab, and Figures keeps live drawing instances beside each figure.)
  • Declared, never invented. Every value is declared in uiState.js with its default (CLAUDE.md: "a global value must be declared in its state object").
  • Written through immediately. Tabs write state as the user works, so switching tabs needs no save step.
  • Not kept across a page reload. A reload starts from the defaults.

What is in it

overlaywhether an overlay is up, its type and title

Every tab area also has needsUpdate.

The three signals setUI reads

  • needsUpdate: true after a Rebuild & Validate; the tab is re-initialized (with restored = true) and the flag cleared.
  • saved: if set, the tab's restore() rebuilds the screen from it; if null, its init(false) does.
  • launch.pending: after the tab is up, jump to launch.targetTab.

"Switching Tabs" (setUI.html) has the table of which tabs restore and which re-init.

Active versus saved

Within a tab's area, the active... fields say what is selected right now; saved is the recipe for rebuilding the screen on return. For Patterns and Gallery the tab writes both on every move. For Draw, Utilities and Figures, saved stays null and init rebuilds from the active fields and tabs.

Other window globals

The end of uiState.js lists the other values code reaches through window: window.overlayManager, and the third-party window.Coloris and window.jQuery. The interactor also puts armInteractor and disarmInteractor there, and the registry objects live in window.drawRegistry.
