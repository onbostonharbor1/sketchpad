setUI.js — Switching Tabs

Rewritten 27 October 2026 against the current code. Changes since the earlier page: a third signal, needsUpdate, now comes first; restore clears the regions too (the old page said it did not); start-up also sets up the canvas layers; errors name the stage that failed. And one thing the old page implied but the code never does: setUI does not call any tab's save().

setUI.js is the switchboard for the six main tabs. It renders nothing itself. It decides how a tab should be brought up, then hands over to that tab's TabSpec.

The routing table

TabRegistry = { home, draw, patterns, gallery, utilities, figures }

Each value is a TabSpec with at least init(restored) and restore().

setUI(tab): what happens on a tab click

  1. Turn off any Prev/Next overlay.
  2. Reject an unknown tab name.
  3. Write the tab name to session storage (sketchpad.lastActiveTab; nothing reads it back at present).
  4. Apply the tab's theme class to #wrapper, before anything is built, so new DOM is styled right away.
  5. activateTab(tab): init or restore (below).
  6. If a launch intent is pending (uiState.launch.pending), clear the pending flag first, then call setUI(targetTab) unless it is already active. Clearing first prevents a loop.

Each step records its name; if anything throws, the console says which step it was.

activateTab: init or restore

if  uiState[tab].needsUpdate      -> clear it, clearDivs(), init(true)
elif uiState[tab].saved            -> clearDivs(), restore()
else                               -> clearDivs(), init(false)
then uiState.activeTab = tab, highlight its button
  • needsUpdate is set on every tab by syncSystemStateAfterRebuild() after a Rebuild & Validate, so each tab reloads its manifests the next time it is shown.
  • saved is whatever the tab itself has written there. setUI never calls save().
  • Both paths start with clearDivs() (uiUtilities.js).

Either way, every tab comes back to what it showed, because each keeps its state in uiState as you work. The real difference is only which function rebuilds the screen. The end-of-work list in PHASES.md (items 4 and 6) proposes settling on one convention.

Start-up

On DOMContentLoaded: set up the menu manager, the panel overlays and the canvas layers; wire each main tab button to setUI; then setUI("START_APP"), which brings up Home (with init). If start-up fails, the message goes into #text so the page is not just blank. A page reload always starts fresh: nothing is read back from session storage.

The launch intent

One tab can ask for another to open with context, without calling it directly. Home does this for built-in Draw objects: it fills uiState.launch (pending, source, target, type, registry key) and calls setUI("draw"). Draw's init reads the intent, clears it, and opens the object.
