Parameter Controls — Sliders and Their Kin

Rewritten 27 October 2026 against the current code. ui/parameterControls.js is now a 27-line forwarder; the real code is split by job under ui/controls/. The point-picker widgets the earlier page described are switched off (handles are dragged by interactor.js instead), and there are new widgets: number, accordion and thumbnail grid. The schema flags are listed on the companion page "Control Schema Flags" (parameterControls2.html).

Given an object's control schema and its current values, this system builds the controls in the left action panel and, when one changes, updates the value and asks for a redraw. Draw, Figures and runnable scripts all use it.

buildParameterControls(sourceInfo, targetTabId, render)

Two kinds of source:

  • Draw-style (Draw, Figures): { drawRegistry, parameters, redrawHandler, onParamChange }. The schema is drawRegistry.controls.
  • Script-style: the script's scriptInfo, { controls, parameters, redrawHandler }.

Which one is chosen: a targetTabId starting "tab-draw" means Draw-style, "tab-scripts" means script-style; anything else (including the default "tab-generic") is decided by the source's shape (controls present: script; drawRegistry present: Draw). Figures passes "tab-draw". The result is a normalized list, { key, label, widget, min, max, step, options, value, default, ... }, drawn at once unless render is false.

Drawing the panel

  • Writes into #drawControls inside #action (created if missing), emptied first, so other things in #action survive. #action must exist.
  • Controls marked as interface controls go to #interface-controls instead.
  • No controls: "(no parameters)".
  • Each entry goes through buildSingleControl(): a div.ctrl-field with a label and the widget. A hidden widget returns nothing and takes no room.

pointPicker and pointPickerArray are still named in the constants, but their cases in buildSingleControl are commented out, so such a key falls through to a plain input box. Two registry objects still declare one (boxes, regularPursuit, for a midpoint).

When a control changes

  1. The new value goes into info.parameters[key] (for Draw and Figures, that is the object's own params, so the drawing data changes directly).
  2. info.onParamChange(), if there is one (Draw marks the subtab with "*"; Figures passes an empty function).
  3. info.redrawHandler().
  4. If the control asks for it (rebuildControls, or showsGroup on a select or radio), the whole panel is rebuilt.
