Control Grouping System - Implementation Guide

What Was Implemented

A declarative grouping mechanism for conditional control visibility in parameterControls.js.

No changes required to scriptRunner, drawRunner, or figuresRunner - the grouping logic is entirely self-contained within parameterControls.js.

How It Works

1. Declare a Trigger Control

Mark a select or radio control with showsGroup: true:

controls: {
  boundaryType: { 
    widget: "select", 
    options: ["circle", "polygon", "ellipse", "modulated"],
    showsGroup: true  // <-- This control determines which group is visible
  }
}

2. Group Your Controls

Add belongsToGroup to controls that should only appear for specific trigger values:

controls: {
  // Always visible (no belongsToGroup)
  centerX: { widget: "range", min: 0, max: 700 },
  
  // Trigger control
  boundaryType: { 
    widget: "select", 
    options: ["circle", "polygon", "ellipse"],
    showsGroup: true
  },
  
  // Polygon group (only when boundaryType === "polygon")
  groupPolygon: { 
    widget: "staticText", 
    text: "--- Polygon ---",
    belongsToGroup: "polygon"
  },
  sides: { 
    widget: "range", 
    min: 3, max: 8,
    belongsToGroup: "polygon"
  },
  
  // Ellipse group (only when boundaryType === "ellipse")
  groupEllipse: { 
    widget: "staticText", 
    text: "--- Ellipse ---",
    belongsToGroup: "ellipse"
  },
  ellipseRatio: { 
    widget: "range",
    belongsToGroup: "ellipse"
  }
}

3. That's It!

When the user changes boundaryType to "polygon":

  • All controls with belongsToGroup: "polygon" become visible
  • All other grouped controls are hidden
  • Controls without belongsToGroup remain visible

Matching Logic

The group name in belongsToGroup must exactly match the value of the trigger control:

boundaryType: { options: ["circle", "polygon"] }  // trigger values

sides: { belongsToGroup: "polygon" }  // matches when boundaryType === "polygon"

Multiple Trigger Controls

You can have multiple trigger controls in the same schema. Each one independently controls its own groups:

controls: {
  shapeType: { 
    widget: "select", 
    options: ["circle", "square"],
    showsGroup: true 
  },
  fillType: { 
    widget: "select", 
    options: ["solid", "gradient"],
    showsGroup: true 
  },
  
  // Shape groups
  radius: { belongsToGroup: "circle" },
  size: { belongsToGroup: "square" },
  
  // Fill groups
  color: { belongsToGroup: "solid" },
  startColor: { belongsToGroup: "gradient" },
  endColor: { belongsToGroup: "gradient" }
}

State Preservation

Hidden controls keep their values! When you switch from "polygon" to "ellipse" and back:

  • sides: 6 remains 6 even while hidden
  • Parameter values persist in sourceInfo.parameters
  • Only visibility changes, not state

Backward Compatibility

Scripts without showsGroup or belongsToGroup continue working exactly as before. The grouping system is opt-in.

Works Everywhere

This system automatically works in:

  • Gallery Scripts (scriptRunner.js)
  • Draw objects (drawRunner.js)
  • Figures (figuresRunner.js)

No special integration code needed in any runner.

Implementation Details

Core Functions Modified

  1. filterControlsByActiveGroups() - New helper function that filters control lists
  2. buildDrawParameterData() - Applies group filtering before returning
  3. buildScriptParameterData() - Applies group filtering before returning
  4. setSelectControl() - Checks for showsGroup and calls rebuildControls()
  5. setRadioControl() - Checks for showsGroup and calls rebuildControls()
  6. rebuildControls() - New function that triggers full control panel rebuild

Rebuild Flow

User changes trigger control (e.g., boundaryType) ↓ Change handler detects def.showsGroup === true ↓ Calls rebuildControls(sourceInfo, tabId) ↓ Calls buildParameterControls(sourceInfo, tabId, true) ↓ buildScriptParameterData() or buildDrawParameterData() ↓ filterControlsByActiveGroups() filters the control list ↓ renderParameterControls() rebuilds the DOM ↓ Control panel updates (hidden controls removed, new controls appear)
Example: See the file concentricStitch_grouped.js for a complete working implementation using this system.
