fileLayer.js — Reading Files and Building Paths

Rewritten 27 October 2026 against the current code. The main changes since the earlier page: every path is now absolute (/patterns/...; the old ../patterns/... forms are gone and a relative path is refused), exists() uses GET instead of HEAD, and the path helpers have been adopted by manifest.js.

fileLayer is the browser's read-only way to reach files through the local web server, plus one place where paths are built so every tab builds them the same way. It knows nothing about tabs, the screen, or what the files mean. (Writing files is the Node service's job; see nodeLayer.js.)

A trap with exists(). The Vite development server answers an unknown path with index.html and status 200, so exists() can say true for a file that is not there. That is why the Home tab reads its manifest directly instead of letting the manifest system probe for a directory registry that does not exist, and why scriptRunner.js checks the content type before importing a script.

listDirectory depends on the server producing an HTML listing. Its one caller is a drawRegistry branch in manifest.get() that nothing reaches (no code asks for manifest.get("drawRegistry")), and that branch would find nothing anyway: it passes a relative path and filters the returned strings for an isDirectory field they do not have.

The script helpers take a name with or without .js and always give exactly one.

In practice only the three manifest helpers are used (by manifest.js). The tabs still write their own script and help paths inline (for example `/patterns/${category}/${filename}.js` in patternsDisplay.js). Moving them onto these helpers is unfinished work, not a problem: the paths agree.

Old names

normalizeHelpPath, normalizeScriptPath, normalizePatternPath, normalizeGalleryScript and normalizeUtilityPath each just call the matching path helper. Nothing calls them; they can go when convenient.
