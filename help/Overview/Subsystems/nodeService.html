The Node Service — What node/ Does

Written 16 November 2026 from the headers and code in node/. The browser side of the same conversation is on the nodeLayer.js page; running Sketchpad away from your own computer is on Running in a Codespace.

1. Why there is a Node service at all

A web page cannot write files, list folders or start programs. Everything in Sketchpad that touches the disk beyond loading its own files goes through a small program that runs beside the page: saving a figure, writing a thumbnail, reading the log files, listing a category, opening a file in VS Code. That program is the Node service. It only listens on this computer (127.0.0.1, port 5174).

2. How a request travels

  1. UI code calls nodeDispatch(requestName, payload) (ui/nodeLayer.js).
  2. The page posts {requestName, payload} to /dispatch on its own server. Vite passes it on to port 5174 (vite.config.js), which is why the same setup works in a Codespace.
  3. sketchpadServer.mjs checks the request came from Sketchpad's own page, reads the body and calls the dispatcher.
  4. sketchpadService.mjs looks the request name up and runs one handler. It does nothing else.
  5. The handler does the file work and returns JSON. A bad request gets HTTP 400 with a plain message; a real failure (a disk error, a bug) gets 500. An unknown request name is a 400, never silently ignored.

Every path a handler builds from text the browser sent goes through safePaths.mjs first, so a request cannot reach outside the folder it is meant for.

3. The two servers, and starting them

Sketchpad is two programs: Vite serves the page on port 5173, and the Node service on 5174. sketchpad.bat runs npm run start:sketchpad, which first runs check:ports (it stops the start if either port is already in use), then starts both under concurrently -k so that closing one stops the other. The service also exits with a plain message if its own port is taken.

4. The files, and what each is responsible for

The front door

FileResponsibility
sketchpadServer.mjsThe HTTP server. Accepts POST /dispatch only, refuses pages from other sites, limits the body size (50 MB, for thumbnails and PNG uploads), turns errors into 400 or 500, and shuts down cleanly. It knows nothing about what any request means.
sketchpadService.mjsThe dispatcher: a map from request name to handler. Its header lists every request the service accepts.
safePaths.mjsThe guards: RequestError (a bad request, reported as 400), assertSimpleName (a name with no slashes or tricks) and isInside (a path stays inside its folder). Every handler uses these.
serviceFileHelpers.mjsSmall file helpers the handlers share: read and write JSON, write a file atomically (to a temporary file, then rename, so a crash cannot leave half a file), check that a file or folder exists, make a timestamp for a file name.

The request files (one family each)

FileRequestsResponsibility
libraryIndex.mjslistLibrary, listHomeItemsWorks out every category list and the Home list from the folders on disk. A manifest only adds titles, statuses and order; a file with no entry still appears. There is no file watcher; a new file shows up the next time the list is read.
manifestRequests.mjseditManifestEntry, archiveItemChanges one item's title or status in its manifest, or moves an item to archive/ and drops its entry.
writerRequests.mjswritePatternThumbnail, writePatternFromDrawRegistry, writeGalleryPatternPng, writeHelpFileWrites files from data the browser sends: a pattern's thumbnail, a Pattern script made from a Draw object, a Gallery PNG, a help page.
thumbnailRequests.mjswriteThumbnailWrites the picture shown for an item in a category list (images/thumb_<name>.png). It never creates a category folder.
figureFiles.mjssaveFigureSaves a figure from the Figures tab as one JSON file in figures/<category>/ with a manifest entry. If the name already exists it answers "exists" and writes nothing, unless told to overwrite. Reading a saved figure needs no request; the page fetches the file directly.
createFigureService.mjscreateFigureThe earlier Create Figure feature: builds a figure file from a list of Draw objects.
secondaryRequests.mjssaveSecondaryObject, readSecondaryObject, archiveSecondaryObject, getSecondaryManifest, getPrimaryObjectsWithSecondariesSaved Draw settings: save one, read one, archive one, and list them.
logAndEditorRequests.mjslistLogFiles, readLogFile, appendErrorLog, openInEditorReads the files in utilities/logfiles, appends errors to errors_<date>.txt, and opens a project file in VS Code.
scriptHistoryRequests.mjslistScriptHistory, readScriptHistoryVersion, listIdeabookScriptsReads VS Code's local history of a script (read only) so an older version can be listed and run, and lists the Ideabook hint scripts.
homeListRequests.mjswriteChecklist, listHelpTopicsSaves Home > Checklist's file and lists the topics in each Help group.
maintain_manifests.mjsmanifestMaintenanceRebuilds and validates every manifest. Run from Utilities > Rebuild & Validate; it is no longer part of start-up.

Tools run by hand or by a script

These are not requests. They run on their own and the running app does not depend on them.

FileResponsibility
check_ports.mjsSays whether ports 5173 and 5174 are free; exits with an error if not.
generateHelpManifest.mjsScans help/ and writes help/manifest.json. Run it after adding or removing a help page.
copyBuildDocs.mjsFills Home > Help > Build Documents from the documents in docs/ (npm run help:builddocs).
makeHelpPdf.mjsMakes one PDF of the Help Overview and the Tutorials (npm run help:pdf; the app must be running).

5. Things worth knowing

  • Atomic writes. Files are written to a temporary name and renamed, so an interrupted write cannot corrupt a manifest or figure.
  • Where changes go. A new kind of request needs a handler in a request file, a line in the dispatcher's map and an entry in its header list, and a call from the browser through nodeDispatch.
  • Requests do not delete your files. Archiving moves a file to archive/. The only deletions in the service are its own temporary files. (The tool copyBuildDocs.mjs does clear help/BuildDocs before refilling it; that folder is made by the tool and is not edited by hand.)
  • Settings. SKETCHPAD_PORT changes the service's port (set it for Vite too). SKETCHPAD_ROOT points maintain_manifests.mjs and copyBuildDocs.mjs at a scratch copy of the project, for testing. The request handlers use paths such as ./figures, which means the folder the service was started from, so the service must be started from the project folder (sketchpad.bat does this).
