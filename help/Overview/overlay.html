```html Help Treatise — overlay.js (Overlay Manager + Help Overlay Loader)

overlay.js — Overlay Manager (Panel + Canvas Layers) and Help Overlay Loader

This page is intentionally “raw help HTML”: it is written as a single self-contained page so you can drop it into your help system as-is, and/or split it later into smaller pages. The discussion is based on one file:

  • ui/overlay.js
Scope of this treatise
1) The two overlay worlds: panel overlays vs canvas overlays.
2) overlayManager API and its invariants (register/show/hide/clear).
3) initOverlay(): the one-time wiring step that binds DOM elements to overlay layers.
4) The help overlay features: showHelpOverlay and related helpers.

1. What this file is in the Sketchpad architecture

Sketchpad uses “overlays” for two different kinds of UI:

  • Panel overlays (HTML panels layered above the app UI): help pages, forms, debug panels.
  • Canvas overlays (stacked canvases layered above the drawing canvas): interaction handles, bounding boxes, nodes, guides.

overlay.js provides a single manager for both overlay worlds, plus a help loader that can fetch a help HTML page and display it in the help overlay.

Key idea
The overlay system is deliberately simple: overlays are just DOM elements that are shown/hidden and optionally filled with HTML. No framework. No implicit state.

2. The overlayManager object

This file exports a singleton manager: 

export const overlayManager = { ... };

It tracks two separate registries:

  • layers — panel overlay DOM elements (help/forms/debug)
  • canvasLayers — canvas overlay DOM elements (interaction/bbox/nodes/guides)
Important naming distinction
“Panel overlays” are not canvas elements; they are HTML containers used for UI panels.
“Canvas overlays” are separate canvas layers used for drawing interactive visuals on top of the sketchpad.

3. Panel overlay API

3.1 register(name, element)

Registers a panel overlay DOM element under a logical name, fail-fast if args are missing: 

overlayManager.register("help",  helpEl);
overlayManager.register("forms", formsEl);
overlayManager.register("debug", debugEl);
Invariant
You can only show/hide/clear a panel layer that has been registered.

3.2 show(name, html)

Displays a panel overlay by:

  • Looking up the registered element by name
  • Setting innerHTML to the provided HTML
  • Setting style.display = "block"
Fail-fast
If the layer name is unknown, show throws immediately.

3.3 hide(name)

Hides a registered panel layer by setting style.display = "none". It does not clear the HTML.

3.4 clearLayer(name)

Clears a registered panel layer by:

  • Setting innerHTML = ""
  • Setting style.display = "none"

This is used when you want “no content” as well as “not visible”.

3.5 clearAll()

Clears and hides all registered panel layers (help/forms/debug) in a single sweep.

Important boundary
clearAll() clears panel overlays only, not canvas overlays.

4. Canvas overlay API

Canvas overlays are handled in a parallel registry:

  • registerCanvas(name, element)
  • getCanvasLayer(name)

4.1 registerCanvas(name, element)

Registers a canvas overlay element (typically a stacked canvas) under a logical name: 

overlayManager.registerCanvas("interaction", inter);
overlayManager.registerCanvas("bbox", bbox);
overlayManager.registerCanvas("nodes", nodes);
overlayManager.registerCanvas("guides", guides);
Why register?
Your interaction subsystems can ask for “nodes” or “bbox” without hardcoding element IDs.

4.2 getCanvasLayer(name)

Returns the registered element for a canvas overlay layer. It is fail-fast if the name is unknown. 

const nodesCanvas = overlayManager.getCanvasLayer("nodes");
Fail-fast is intentional
If a canvas overlay layer is missing from the DOM, you want a hard crash during startup, not silent behavior where interactions “just don’t work”.

5. initOverlay(): the one-time wiring step

initOverlay() must be called once during application startup (your comment indicates: “CALL ONCE IN onDomContentLoaded()”).

5.1 What initOverlay does (exact sequence)

  1. Fetch panel overlay elements by ID: overlay-help, overlay-forms, overlay-debug.
  2. If any are missing, throw (fail-fast).
  3. Register them as panel layers: help, forms, debug.
  4. Fetch canvas overlay elements by ID: interaction-layer, bbox-layer, nodes-layer, guides-layer.
  5. If any are missing, throw (fail-fast).
  6. Register them as canvas layers: interaction, bbox, nodes, guides.
  7. Wire the close button (#overlayClose) so it:
    • Hides #overlayContainer
    • Calls overlayManager.clearAll() (panel overlays only)
Startup contract
After initOverlay() runs successfully, all overlay layers are registered and ready. If something is missing, startup crashes immediately, which makes layout wiring errors obvious.

6. Legacy exposure: window.overlayManager

After defining overlayManager, the file assigns: 

window.overlayManager = overlayManager;

This is explicitly noted as “Expose for older code”. It allows older non-module or transitional code to access the overlay manager via the global window.

Interpretation
Modern ES-module code should import overlayManager. The global is a compatibility bridge, not the preferred access path.

7. Help overlay features

This file defines several helper functions on top of overlayManager. The most important is showHelpOverlay(helpPath, titleText).

7.1 showHelp(text) and hideHelp()

These are simple helpers that treat “help” as a panel overlay layer:

  • showHelp(text) wraps text in a help-block div and calls overlayManager.show("help", html).
  • hideHelp() calls overlayManager.hide("help").
Intent
These are “quick help” helpers. They are not the full help-page loader.

7.2 openOverlay(html) and closeOverlay()

These are described in the file as “rarely used”. They are simple aliases that show/hide the help panel layer.

Terminology note
Despite their generic names, openOverlay and closeOverlay operate specifically on the help panel layer in this implementation.

7.3 showHelpOverlay(helpPath, titleText): full help HTML loader

This is the “real” help overlay workflow used by the Help menu system. It:

  1. Fetches the help HTML file from helpPath.
  2. Parses the HTML string into a DOM document using DOMParser.
  3. Extracts the body inner HTML (or falls back to the full HTML string if needed).
  4. Wraps it in a container: <div class='overlayHelp'>...</div>
  5. Calls overlayManager.show("help", finalHtml).
  6. Sets the overlay title element (#overlayTitle) to: titleText + " Help"
  7. Sets #overlayContainer display to block (making the overlay system visible).
Key architectural separation
menuManager decides whether Help is enabled.
overlay.js is responsible for loading and displaying the help HTML.
Error handling note
In the pasted version, showHelpOverlay does not check resp.ok and does not attach a catch. If fetch fails, you will get a console error and the overlay may not change. That may be acceptable because your Help menu is supposed to be enabled only when help exists.

8. How this file fits with the rest of Sketchpad

In the surrounding architecture:

  • Startup calls initOverlay() once to register all overlay DOM elements.
  • Tabs and utilities call overlayManager.show/hide/clear for panel overlays (help/forms/debug).
  • Interaction subsystems call overlayManager.getCanvasLayer(...) to draw on the correct stacked canvas.
  • The caption menu Help item calls showHelpOverlay(path, helpKey) when selected.

9. Summary checklist

  • Two overlay registries: panel overlays (layers) and canvas overlays (canvasLayers).
  • Fail-fast registration: missing overlay elements are detected at init time.
  • Panel API: register/show/hide/clearLayer/clearAll (clearAll affects panel overlays only).
  • Canvas API: registerCanvas/getCanvasLayer (explicit retrieval for interaction drawing).
  • initOverlay wires DOM IDs to logical overlay names and hooks the close button.
  • Help loader: showHelpOverlay fetches help HTML, extracts body content, displays it in the help layer, and shows the overlay container.
  • Compatibility: window.overlayManager is provided for older code.

End of treatise.
```
